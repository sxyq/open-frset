## 2. 根因：指纹不匹配（tccd 日志实锤）

```
2026-10-14 12:14:21.832 tccd [com.apple.TCC:access]
  Failed to match existing code requirement for subject com.maoux.frset
  and service kTCCServiceScreenCapture
2026-10-14 12:14:24.490 tccd [com.apple.TCC:access]
  Failed to match existing code requirement for subject com.maoux.frset
  and service kTCCServiceScreenCapture
```

**解读**：系统里存在 Frset 的屏幕录制授权记录（你看到的"已给权限"），但该记录绑定的是**旧版本（10:44 最终重签之前）的指纹**；当前 App 的指纹与记录不符 → tccd 拒绝放行 → App 每次截图都认为"没有权限"→ 反复请求。

**时间线**：
1. 09:21~10:17 期间，你在系统设置里为当时的版本授权（屏幕录制 10:17:16）；
2. 10:44 进行了**最后一次重签名**（追加补丁 C 并重打包）→ 指纹变化 → 上述授权全部作废；
3. 此后无论你怎么重新勾选（记录仍是旧指纹，或勾选动作没有生成新指纹绑定），App 都无法通过校验 → 一直请求权限。

**所以：是不是之前改的时候改出问题的？**
- 权限问题：**是"重签名"这一解锁必要步骤的直接副作用**（机制上必然，不是补丁逻辑 bug）；
- 当时的"OCR 报错闪退"：是另外两个历史问题——① Helper 因签名不匹配被系统击落（09:52 崩溃，已于 10:10 修复）；② 权益校验补丁初版（case 0）缺陷导致字符串解引用崩溃（09:42/09:51 崩溃，已改为 case 3 修复）。**两者均已修复，10:44 后零新崩溃**。

## 4. 待执行：重新授权（用户操作，一次性，约 1 分钟）

由于旧记录已清除，需让 App 用**当前指纹**重新登记一次授权：

1. **打开 Frset**（菜单栏出现图标），点击"截图"——此时 App 会提示需要屏幕录制权限；
2. 打开 **系统设置 → 隐私与安全性 → 屏幕录制**，找到 Frset，**把开关打开**（新记录会绑定当前版本指纹）；
3. 系统会提示"需要退出并重新打开 App"——点提示按钮，或手动：`退出 Frset 再打开`（权限只在进程启动时生效）；
4. 再点截图 → 应恢复正常；顺带测试一次"截图 OCR"。

> 若之后**自动粘贴/全局快捷键**也提示权限，用完全相同的方法处理"辅助功能"那一项即可。
> ⚠️ 完成授权后请**不要再让我们对 App 重签名**（重签=授权再次作废）。这条已写进《维护手册》。
