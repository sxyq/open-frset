## 5. 事故与修复记录：12:28 启动崩溃（已修复）

**现象**：首批 PostHog 域名补丁使用「短域名 + NUL 填充」，构建后 App 启动即崩溃。
- 崩溃报告：`crash-20261014-122856-nul-trap.ips`（已归档）；`EXC_BREAKPOINT`，栈在 `applicationDidFinishLaunching` → PostHog 初始化 → `URL`/`CharacterSet` 相关代码。

**根因（反汇编实锤）**：
1. PostHog 初始化函数（0x100307xxx）直接加载补丁后的字符串，反汇编注释可见 `literal pool for: "https://ph.invalid"`；
2. **Swift 常量字符串自带长度头**（位于字符数据前 0x20 字节）——NUL 填充被算入字符串本体；
3. 构造出的字符串含控制字符 → `URL(string:)` 返回 nil → 代码强解包 → Swift trap 崩溃。

**修复**：改为**零 NUL** 的全字符等长替换（即 §4 最终表）。Sentry 条目初版即为零 NUL，未受此影响。
**教训（已写入维护手册铁律）**：任何字符串补丁必须同时满足「等长 + 零 NUL」。

## 7. 残留与边界（如实记录）

1. **x86_64 slice 未打任何补丁**（含遥测）；本机 arm64 原生运行不受影响；Rosetta 下才会回到原始逻辑。
2. 遥测代码仍在运行（PostHog/Sentry SDK 照常初始化），但出口域名已死——**零 egress**；SDK 重试均快速失败，无副作用。
3. 钥匙串锚点条目保留（本地），本地读写行为未消除（见 §3 边界结论）。
4. 用户环境有本地代理（Clash 系），死域名会被 fake-IP 截获后拒绝——依然无法到达真实服务，结论不变。
5. 未来如需再动 App 二进制：先读维护手册"字符串补丁铁律"，改完必须重走「重签 → 安装 → 授权」。

## 9. 补记（14:10）：钥匙串弹窗「完整条件」查明与**永久修复**

> 触发：用户反馈"重启后仍会申请钥匙串（始终允许后亦然）"——要求查清完整条件并彻底删除。

### 9.1 完整条件（证据链，全部实测）

| 证据 | 内容 |
|---|---|
| **弹窗时的系统 ACL**（securityd `kcacl` 日志） | `displaying keychain prompt for /Applications/Frset.app; ACL: ThresholdAclSubject(1 of 6)[ 5×CodeSignatureAclSubject(cdhash H"2fcfda8e…"/"e8308ac2…"/"0960720a…"/"c04cdf89…"/extracted版"1efc57f3…") + 1×Keychain内部项 ]` |
| **机制** | 条目 ACL = "6 项历史签名满足其一"；**列表里全是旧构建**——用户每次拿到的**新构建都不在列表** → 必弹；"始终允许"只把"当次构建"追加进列表——**只要再重签一次，就再次弹** |
| **App 的完整访问清单**（interpose `SecItem*` 实测） | 启动即**高频读取**唯一一个条目：`class=genp, service=com.maoux.frset.anchor, account=primary_token`（无其他服务） |
| **条目信息**（security find） | `com.maoux.frset.anchor`（acct=`primary_token`），旧条目创建于 2026-10-13，ACL 含 5 个历史 cdhash |

### 9.2 永久修复（已执行并验证）

1. **删除旧条目**：`security delete-generic-password -s com.maoux.frset.anchor` → **成功且无弹窗**（旧 ACL 一并消失）；
2. **App 自动重建**：下次启动时 App 侧读不到 → 自建新条目（实测创建时间 = 启动时刻 14:09:40，**新条目 ACL = 当前构建自己**）；
3. **验证**：
   - 删除后第 1 次启动：**零 prompt**（SecurityAgent 日志为空）；
   - **第 2 次启动（条目已存在）：零 prompt** ✓；
   - 条目稳定：`mdat == cdat`（未再被改写）；
   - interpose 复测：海量 CopyMatching 调用**全程零弹窗** ✓。
